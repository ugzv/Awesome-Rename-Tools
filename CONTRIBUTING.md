# Contributing

Thanks for helping improve Awesome Rename Tools.

## Before You Submit

- Search the README first to avoid duplicate entries.
- Open one pull request per item or tightly related fix.
- Use a specific PR title such as `Add nomino to Command Line Tools`.
- Make sure the link is live and points to the canonical project page.

## Entry Format

Use this exact format:

```md
- [Project Name](https://example.com) - Short, factual description. `Free`
```

Rules:

- Start the description with a capital letter.
- End the description with a period.
- Keep the description to one sentence when possible.
- Do not use promotional wording such as "best", "amazing", "ultimate", or "world-class".
- Prefer the GitHub repository URL for open-source projects.
- Use the official product site for commercial tools, app stores, or built-in platform features.

## Labels

Use short inline labels only when they add useful context:

- `Free`
- `Paid`
- `Stale`
- `Legacy`

Only add `Stale` or `Legacy` when there is clear evidence that maintenance status affects adoption.

## Quality Bar

Entries should be:

- Relevant to file renaming, filename cleanup, metadata-driven naming, or tightly related organization workflows.
- Useful to more than a niche internal audience.
- Maintained or still practically usable.
- Well documented enough that a new user can install or try them.

## Sorting

- Keep sections in the existing order.
- Keep entries alphabetized within each section.

## Commercial Tools

Commercial tools are allowed, but they must be labeled `Paid`.

## Badge for Listed Projects
